# 会议中实时语音情绪反馈

用户已于 2026-10-30 确认本方案并授权实施。

- 复用当前选择的录音来源与 16 kHz PCM，独立于字幕识别运行本地 emotion2vec+ base。音频不上传。
- 最近 6 秒为一个窗口，每 3 秒更新；推理只允许一个在途请求和一个最新窗口，丢弃积压窗口。实际延迟需要本机测试。
- 展示中性、愉快、悲伤、愤怒、恐惧、厌恶、惊讶七种模型类别，其他与未知归为无法确定。显示主要类别和至多一个候选及模型分数；分数不是已校准的概率，多候选不等于同时存在多种情绪。
- 没有足够有效声音、低分、加载、失败、暂停、停止均有明确状态；不把音量或文本关键词伪装成情绪结果。
- 不区分发言人的实时情绪，只描述当前所选音源最近一段声音。混合多人声音需谨慎解读。
- 会后移除个人情绪词计数、个人声学与逐人 openSMILE 提取和展示。保留字幕说话人区分、发言占比、轮次、清晰度、音频播放和基础声学分析。会后总体文本信号改称文本线索，避免与实时语音模型混淆。
- 使用独立项目虚拟环境 `.venv-emotion`，模型放在 `models/emotion2vec_plus_base`；安装脚本负责首次下载，运行期只加载本地文件。缺失时明确提示安装命令，录音字幕继续。
- worker 以常驻 Python 子进程加载一次模型；NDJSON 传递窗口与分数。按 sessionId 和录音代次隔离；暂停清空历史窗口，停止/重录使旧回调失效。
- 验证分窗、限流、旧结果丢弃、暂停/停止/重启、错误恢复及候选展示，跑现有回归；真实模型用本地示例或已有音频验证输入、输出和推理耗时。真实会议情绪准确率需用户回听评估，不以程序测试替代。

已核对来源：https://github.com/ddlBoJack/emotion2vec 和 https://huggingface.co/emotion2vec/emotion2vec_plus_base 。其他路径（规则声学反馈、SenseVoice 替换/新增推理）分别缺少情绪能力或重复现有 ASR，因此采用独立 SER。
