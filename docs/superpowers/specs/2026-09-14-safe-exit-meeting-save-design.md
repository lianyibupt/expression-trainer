# 会议安全退出与完整保存设计

日期：2026-09-14
状态：已确认

## 背景

应用当前把多场会议及“最近关闭”的会议保存在 renderer 内存中。关闭会议标签只隐藏会议，
但关闭主窗口或退出应用时没有未保存检查；尚未持久化的逐字稿、音频引用、说话人片段、
纪要和报告会随进程结束而丢失。

当前说话人能力也需要明确产品边界：它在 Qwen3-ASR 最终稿阶段按本地声学特征做匿名
音色聚类，输出“说话人 1/2”等标签；不在实时字幕阶段运行，也不识别真实身份。

## 目标

1. 所有应用退出入口使用同一套未保存检查，包括关闭主窗口、macOS `Command+Q` 和应用菜单退出。
2. 若有录音或最终稿任务，退出时先结束录音并等待 Qwen3-ASR 最终稿完成。
3. 保存所有会议当前已经存在的信息；全部保存成功后才真正退出。
4. 任何转写或保存失败都不得静默退出，必须让用户重试、降级保存或取消退出。
5. 明确“按音色区分说话人”是匿名的会后聚类，而非实时身份识别。

## 非目标

- 不把匿名说话人标签关联到真实姓名。
- 不在实时 Paraformer 字幕中增加说话人分离。
- 不替换现有 Qwen3-ASR 或说话人聚类算法。
- 不在退出时自动调用 LLM 生成尚不存在的纪要或报告。
- 不自动覆盖用户已经编辑的逐字稿；仍沿用现有最终稿/编辑稿冲突规则。

## 用户体验

### 无待处理内容

如果所有会议均无内容，或所有已有内容都已保存且保存后没有变化，应用直接退出。

### 有待处理内容

应用阻止本次关闭并显示统一退出对话框。对话框显示待处理会议数量，以及是否存在：

- 正在录音或正在停止录音；
- Qwen3-ASR 最终稿正在生成；
- 从未保存的会议内容；
- 保存后再次发生的修改；
- 正在执行的保存操作。

对话框提供：

1. **保存全部并退出**：执行安全退出流程；
2. **取消退出**：关闭对话框并继续使用应用；
3. **放弃未保存内容并退出**：弱化显示，并通过第二次确认防止误触。

进入“保存全部并退出”后，页面显示逐场进度，并禁止重复触发退出、创建新会议或开始新录音。

### 失败处理

如果 Qwen3-ASR 最终稿失败，应用保持打开并显示失败会议，提供：

- **重试最终稿**：重新运行该会议的最终转写；
- **保存现有实时稿**：明确接受降级内容，然后继续保存；
- **取消退出**：停止退出流程并返回应用。

如果任意会议保存失败，应用保持打开，列出失败会议和错误，并提供重试或取消退出。已经成功
保存的会议不回滚；重试时仅重新处理失败或其后尚未处理的会议。

## 架构

### 主进程：退出闸门

主进程维护一个退出状态：

- `idle`：正常运行；
- `awaiting-renderer`：已拦截退出，等待 renderer 决策；
- `approved`：renderer 已确认所有内容处理完成，允许真正退出。

主窗口的 `close` 事件以及应用的 `before-quit` 事件统一进入退出闸门。处于 `idle` 时，主进程
阻止退出并向主窗口发送退出请求；处于 `approved` 时不再阻止。重复的关闭或 `Command+Q`
不会创建并行退出流程。

若主窗口尚未完成加载或 renderer 无法响应，主进程不应假定内容已安全保存。用户只能再次
明确选择强制退出，不能静默放行。

### Renderer：退出协调器

`MeetingWorkspace` 负责跨会议编排，因为它持有所有打开及“最近关闭”的 session。退出协调器：

1. 对所有 session 构建退出快照；
2. 判断是否存在待处理内容；
3. 展示确认与进度 UI；
4. 停止当前录音；
5. 等待最终稿；
6. 逐场保存；
7. 全部成功后通知主进程放行退出。

单场会议的停止、等待和保存仍由 `ExpressionTrainer` 提供，不把 ASR 或 artifact 细节复制到
workspace。新增的单场安全保存接口应返回结构化结果，供协调器展示精确状态和错误。

### IPC

preload 暴露最小退出 API：

- 订阅主进程发出的退出请求；
- renderer 完成保存后请求“确认退出”；
- renderer 在用户明确二次确认后请求“放弃并退出”。

所有 IPC 都只传递退出决策和状态，不传递会议正文。正文继续使用现有本地保存 IPC。

## 待保存状态判定

每场会议维护可比较的保存快照。以下任一条件成立即视为待保存：

- 正在录音、正在停止录音或等待最终稿；
- 存在逐字稿文本但从未成功保存；
- 存在录音路径或说话人片段但从未成功保存；
- 存在已生成的纪要或报告但相应 artifact 尚未保存；
- 当前标题、逐字稿版本、逐字稿来源、纪要或报告与最近成功保存快照不同；
- 存在尚未完成的保存 Promise。

“最近关闭”中的 session 与打开的 session 使用完全相同的判定，不因标签已关闭而跳过。

初始空白会议不视为待保存。仅切换面板、打开或关闭标签不产生未保存状态。

## 安全退出数据流

1. 用户触发关闭窗口、应用菜单退出或 `Command+Q`。
2. 主进程阻止关闭并向 renderer 发送退出请求。
3. renderer 扫描全部会议：
   - 无待处理内容：立即确认退出；
   - 有待处理内容：显示退出确认对话框。
4. 用户选择“保存全部并退出”。
5. 若存在正在录音的会议，调用其正常 `stopRecording()`，保留音频且不走丢弃分支。
6. 等待音频 feed、停止流程和 Qwen3-ASR 最终稿任务完成。
7. 最终稿成功时更新逐字稿、匿名说话人片段和版本信息；失败时暂停并请求用户选择。
8. 固定本次退出的逐场快照，依次保存当前已有内容：
   - 当前逐字稿及 metadata；
   - 录音文件；
   - 匿名说话人片段和已有音频分析数据；
   - 已经生成的会议纪要；
   - 已经生成的表达报告。
9. 任一保存失败则停止退出并保留应用；全部成功则通知主进程把状态切到 `approved`。
10. 主进程执行真正退出，不再重复弹窗。

退出过程中如果后台最终稿晚于人工编辑稿返回，继续遵守现有规则：不得静默覆盖人工编辑稿。
用户选择“保存现有实时稿”时，该选择只适用于本次失败会议，并记录在保存状态提示中。

## 说话人行为

- 设置项开启时，Qwen3-ASR 最终稿任务执行本地匿名音色聚类。
- 实时 Paraformer 字幕保持无说话人标签。
- 退出时若最终稿任务尚未完成，安全退出流程等待其完成，从而保存最终说话人片段。
- UI 和说明文案使用“按音色匿名区分说话人，不识别真实身份”。
- 聚类结果可能受相近音色、重叠语音、噪声、远距离拾音和单声道混音影响，个人指标仍需回听核对。

## 并发与一致性

- 同一时刻最多存在一个退出流程。
- 退出流程开始后禁止新建会议、开始录音和再次发起内容生成。
- 已经进行中的保存操作先等待，不与退出保存并发写同一场会议。
- 保存使用进入逐场保存步骤时生成的不可变快照，避免异步操作读到其他 session 的 UI 状态。
- 每个成功保存动作更新对应 session 的保存快照；失败不更新。
- 全部成功是主进程放行退出的唯一普通路径。

## 测试

### 单元测试

- 空白 workspace 判定为可直接退出。
- 未保存逐字稿、音频、说话人片段、纪要、报告分别触发保护。
- 保存后未修改不触发保护；标题或正文再次修改会触发。
- 已关闭 session 仍参与扫描。
- 多次退出请求只产生一个退出流程。
- 单场安全保存按“停止录音 → 等待最终稿 → 固定快照 → 保存”的顺序运行。
- 最终稿失败和 artifact 保存失败不会返回退出批准。

### Browser / 集成测试

- 关闭主窗口、应用菜单退出和 `Command+Q` 进入相同流程。
- 正在录音时退出会先停止并等待最终稿。
- 多场会议（含“最近关闭”）全部保存后只退出一次。
- 最终稿失败时可重试、保存实时稿或取消退出。
- 某场保存失败时应用保持打开，并可只重试剩余失败项。
- “放弃未保存内容并退出”需要二次确认。

### 手工验收

- 使用真实 Qwen3-ASR 长会议验证退出等待过程和进度提示。
- 验证说话人聚类成功后，保存产物含匿名标签与片段。
- 在最终稿失败、保存目录无权限和磁盘空间不足场景下确认应用不会退出。
- 在 macOS 分别验证窗口红色关闭按钮、`Command+Q` 和菜单退出。

## 完成标准

- 用户无法因一次普通关闭操作静默丢失任何已存在的会议信息。
- 正在录音时选择“保存全部并退出”，会先结束录音并等待最终稿。
- 最终稿或任一保存失败时应用保持打开且错误可见。
- 所有会议当前已有信息成功保存后应用才退出。
- 所有退出入口行为一致，且不会出现重复确认或重复保存。
- 说话人文案和行为均明确为会后匿名音色聚类。
