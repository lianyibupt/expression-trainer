# 会议纪要功能设计

## 目标

在现有 Electron 会议录音与表达分析工作台中增加独立的“会议纪要”阶段。用户可以基于“会议原文”单独生成正式会议纪要，不影响实时字幕、表达优化和表达报告。说话人识别结果如果存在，原文中继续使用“说话人 1”“说话人 2”等匿名标签；纪要 Prompt 不要求用户维护人员名单。

## 固定输出结构

会议纪要必须按照以下 Markdown 结构生成，不增加额外一级章节：

```markdown
# 会议纪要

## 会议主题

## 核心结论

## 讨论要点

## 决策事项

| 决策 | 依据 | 影响 |
|------|------|------|

## 待办事项

| 待办事项 | 负责人 | 截止时间 | 状态 |
|----------|------|------|------|

## 风险与未决问题

## 下一步行动
```

原文没有明确给出的负责人、截止时间、状态、依据或影响，统一写为“未明确”，不得由模型推测。没有对应内容的章节保留标题，并写“暂无明确内容”。

## 页面交互

左侧阶段顺序调整为：

1. 实时字幕
2. 会议原文
3. 会议纪要
4. 表达优化
5. 报告

会议纪要阶段包含：

- 生成纪要按钮
- 重新生成按钮（生成成功后可用）
- 复制全文按钮
- 保存为 Markdown 按钮
- 可滚动的纪要正文区
- 无原文时的空状态提示
- 生成中、成功、失败状态提示

生成纪要读取当前“会议原文”编辑器内容。如果编辑器内容已被用户修改，生成时以编辑器当前内容为准，并同步为当前分析原文；生成结果不会覆盖会议原文编辑器。

## 数据流

1. 用户录音结束后获得最终会议原文；或者在“会议原文”阶段手动粘贴文本。
2. 用户切换到“会议纪要”阶段并点击生成。
3. Renderer 通过 preload 暴露的 IPC API 请求主进程生成纪要。
4. Main process 读取当前 AI provider 配置和自定义 Prompt。
5. AI feedback 模块调用专用会议纪要 Prompt。
6. Renderer 渲染 Markdown 结果，并提供复制和保存操作。
7. 如果会议已经保存到会议目录，生成纪要时额外写入同一目录的 `minutes.md`，并更新 `metadata.json` 的文件列表。

## 长文本策略

会议纪要请求不能无条件把超长原文一次发送给模型。实现时提供一个明确的长度上限策略：

- 短文本直接生成正式纪要。
- 超过单次请求阈值时，先按段落切分原文，生成若干“讨论摘要片段”。
- 再将摘要片段合并为一次正式会议纪要请求。
- 合并阶段仍必须遵循固定输出结构，并保留“未明确”规则。
- 任一阶段失败时返回可展示的错误，不修改原文，不影响表达优化和表达报告。

具体阈值应抽成常量，默认值与现有 AI provider 的上下文能力保持保守匹配，不在 UI 中暴露复杂参数。

## 后端接口

新增主进程 IPC：

- `get-meeting-minutes({ fullText })`：返回 `{ success, minutes, error? }`。
- `save-meeting-minutes({ sessionDir, transcript, minutes, stats })`：保存 `minutes.md` 并更新会议元数据。

Preload 暴露对应的 `getMeetingMinutes` 和 `saveMeetingMinutes` 方法。现有 `getFinalReport`、`saveMeetingReport` 行为保持不变。

## 保存格式

独立保存时使用桌面文件保存对话框，文件名格式为：

```text
会议纪要-YYYY-MM-DD-HHmm.md
```

会议目录内保存时，文件名固定为 `minutes.md`，内容包含标题、时间、时长、总字数、原始对话摘要信息和正式纪要。`metadata.json` 增加：

```json
{
  "files": {
    "minutes": "minutes.md"
  }
}
```

## 错误处理

- 没有原文：切换到“会议原文”阶段并提示先录音或粘贴原文。
- AI 请求失败：会议纪要区展示错误，保留上一次已生成内容（如果存在）。
- 保存失败：显示保存失败提示，不清空纪要正文。
- 会议目录不存在或不可写：保留独立保存能力，并在反馈区提示目录保存失败。

## 测试范围

- Prompt 测试：固定章节、表格列、未明确规则存在。
- AI 模块测试：会议纪要请求使用专用 Prompt，返回 provider 内容。
- 会议文件测试：`minutes.md` 保存并更新 `metadata.json`，重复保存覆盖同一会话文件而不创建新会话。
- Renderer 语法检查和现有全量 Node 测试。

## 非目标

- 本次不新增说话人姓名维护或声纹注册界面。
- 本次不自动在录音结束后强制生成纪要。
- 本次不修改实时字幕识别链路。
- 本次不改变现有表达分析报告结构。
