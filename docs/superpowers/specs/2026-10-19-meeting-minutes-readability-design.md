# 会议纪要可读性改进

用户需求：生成内容清晰，页面简单渲染 Markdown，结构化展示。

## 已确认的问题

- `src/app.js` 仅用正则替换标题、粗体和换行，不支持真正的列表、表格，直接插入未转义的模型文本。
- 正式提示词只规定章节，没有按议题组织、保留观点归属、区分既有计划与本次决策的规则。
- 长文中间摘要缺少分歧、修订、条件与片段顺序约束，可能丢失最终合并所需的上下文。

## 实现范围

保留现有七个二级章节。核心结论优先，讨论按议题使用三级标题与简短列表，重复内容合并，关键事实和依据保留。严格区分现状、个人观点、建议、计划、本次决定；没有明确决策或待办时保留空状态，不凑表格、不编造。长文摘要保留顺序、归属、条件、分歧和后续修订，最终整合不能把摘要当作共识证明。

新增独立、无依赖的轻量 Markdown 渲染模块，支持标题、段落、嵌套有序/无序列表、表格、粗体、斜体、行内代码、代码块、引用和分隔线。原始 HTML 作为文本显示，链接不执行；表格在窄屏容器内滚动。样式仅作用于纪要正文。复制、保存继续使用原始 Markdown。

纪要使用较低生成温度；空白输出和因 token 限制截断的结果应报错，避免误保存为完整纪要。重新生成失败时保留旧纪要供复制和保存。

## 验证

用合成样例验证 Markdown 块结构、嵌套列表、表格转义、HTML 安全及整篇 Markdown 代码围栏；用 mock provider 检查短文与长文请求、片段顺序、温度、空输出和截断处理。运行全量 Node 测试及桌面/窄屏浏览器验证。真实模型内容质量需在用户重新生成后进一步评价，测试不声称模型必然遵守提示词。不改动历史会议文件或用户配置。
