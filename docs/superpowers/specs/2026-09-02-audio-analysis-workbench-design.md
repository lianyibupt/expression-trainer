# 音频分析工作台设计

## 目标

在现有 Electron 表达训练应用中增加一个独立的“音频分析”阶段，同时把同一能力接入现有录音结束流程。用户可以上传 `m4a`、`mp3` 或 `wav`，播放并查看波形，选择仅做声学分析或执行本地转写后再分析语气与会议氛围。

## 用户流程

### 独立上传

1. 用户进入“音频分析”阶段。
2. 通过拖拽或文件选择器选择音频。
3. 页面创建播放预览和 Canvas 波形。
4. 用户选择“仅分析音频”或“转写并分析”。
5. 主进程在本机标准化音频并执行分析，前端展示指标、氛围时间线和关键证据。
6. 用户可将分析结果和音频保存为新的会议产物。

### 现有录音

录音结束时保留当前 `meeting.wav`。用户在确认面板保存会议后，使用同一个音频分析服务；已有的转写、说话人区分、报告和纪要流程不被替换。

## 页面结构

新增侧边栏阶段“音频分析”，包含：

- 上传/拖拽区域和文件信息。
- 播放器、播放进度、Canvas 波形和可点击时间线。
- “仅分析音频”和“转写并分析”操作。
- 时长、有效发言占比、静音、能量、说话人数、重叠语音等指标卡片。
- 按时间窗口展示的氛围变化和关键片段。
- 明确的置信度与分析边界提示。

## 技术设计

- 渲染进程只负责 UI、播放和波形绘制，不直接读取 Node 文件系统。
- 主进程通过 IPC 打开本地文件、调用 `ffmpeg` 将输入转成 `16 kHz mono PCM WAV`，并复用本地声学分析模块。
- “转写并分析”复用现有 ASR 配置和 Qwen3-ASR/说话人区分能力。
- 录音和上传路径最终产生同一份分析 JSON，避免指标口径分裂。
- 分析失败时保留原始文件和错误状态，不阻塞已有文本报告。

## 产物

```text
meeting.wav
transcript.md       # 可选
audio-analysis.json
audio-analysis.md
metadata.json
```

## 分析边界

第一版输出可验证的声学和互动信号，不把声学特征直接解释为心理事实。报告使用“可能表现为”和置信度，并保留时间戳证据。混合单声道录音不对单个说话人的音高和音量做强结论。

## 验收标准

- 能选择和拖拽 `m4a`、`mp3`、`wav`。
- 页面可播放音频并显示波形和播放进度。
- “仅分析音频”不依赖 ASR 也能完成。
- “转写并分析”可复用当前本地 ASR 和说话人区分配置。
- 现有录音结束后可以自动进入同一分析能力。
- 分析结果可保存到会议目录，且 metadata 指向所有产物。
- 错误、空文件和不支持格式有明确反馈。
- 单元测试覆盖音频标准化、分析结果和归档；现有测试保持通过。
